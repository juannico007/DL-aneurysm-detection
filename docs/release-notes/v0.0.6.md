## Highlights
- Added a running code where you can choose to run locally or on the cloud (SageMaker).
- Created a versioning system for the models by github username, model name and version.
- View logs of the SageMaker training jobs from command line.
- Pull trained models from S3 based on github username, model name and version.
- Read data from a h5 input

## Motivation

- We came to a point where running locally became unfeasible due to hardware limitations. Therefore, we use Accelerate and SageMaker (from Amazon) to run experiments on the cloud.

- Moving from a small model (1GB) to a 9GB U-Net requires both more RAM and a better GPU; thus, the current code changes the computer specifications on the fly to suit our needs.

- There is also a need for a versioning system in the team, where each of us can run their own experiments.

- In the current code, it is also acceptable to run locally, in case the cloud is not available due to external factors.

- When pulling the data into a new cloud device, it took ~7–8 minutes with the old architecture (a folder with many .npz files). Moreover, the training process was waiting for the data to be read from the disk, so we needed to change how we handle the data. We moved all of the series into an HDF5 file because:
  - it has chunked I/O (reads only what you ask for),
  - fast internal decompression,
  - constant performance (it is based on a B-tree, so it finds the required data quickly)
  - it has page caching, chunk caching, and read-ahead caching.

## Changes in Depth

- there is a new folder `configs` that contains the accelerate configuration for local and cloud runs.

- there is a new folder `scripts` that has 3 scripts:
  - `patch_accelerate_config.py` → Accelerate has a bug, so this file solves it by adding some code into the package files. 
  - `pull_models.py` → pulls trained models from S3 based on github username, model name and version.
  - `show_sagemaker_logs.py` → shows the live logs of a SageMaker training job from command line.

- cli now the hyperparameters on the top of the file, so it is easier to change them. Also, there were added essential code the cloud compatibility. In the end, there will be genereated a `hyperparams.json` file that contains all the hyperparameters used in that run and a metadata.json that contains info about github username, model name and version.

- Now the code is ran using train_entry.py as entrypoint, and you can choose to run locally or on the cloud using the `--mode` argument. The default is local.

- The data_loader was changed to read from a h5 file instead of multiple npz files.
- A new Dataset class was created named AneurysmDataset to read from h5 files.

### Performance
The cloud version needs ~10 minutes to set up the instance, pull the data from S3, and start the training. After that, the training time per epoch is significantly reduced due to better hardware.

| Configuration                   | Model Size | Parameters | Dataset       | Hardware                                             | Training Time per 1 epoch |
| ------------------------------- | ---------- | ---------- | ------------- | ---------------------------------------------------- | -------------- |
| Local | ~3 GB      | 328,001    | 777 CTA scans | RTX 4060 (8 GB VRAM), 24 GB RAM, Intel i9                            | **~3:45 minutes**  |
| Cloud   | ~3 GB      | 328,001     | 777 CTA scans | NVIDIA A10G (24 GB VRAM), 16 GB RAM, AMD EPYC 7R32 | **~1:45 minutes** |


## Run commands: 
- To get the logs for a job, first run the training on cloud mode, wait to see what is the job name, copy somwhere and whenever you want to see the live logs run:
```bash
python scripts/show_sagemaker_logs.py --job-name <job-name>
```

- To pull a trained model from the cloud, you first need to configure in .env file the GITHUB_USER, RUN_MODEL_NAME and RUN_MODEL_VERSION variables. After that, run:
```bash
python scripts/pull_models.py
```
It will generate a foldeer called cloud_models/<GITHUB_USER>/<MODEL_NAME>_<MODEL_VERSION>/ where the trained model and metadata will be stored.


## Migration

1.  Install the new dependencies:
```bash
pip install accelerate[sagemaker] boto3 python-dotenv h5py
```

2. Run the `patch_accelerate_config.py` script to fix the Accelerate bug:

```bash
python3 scripts/patch_accelerate_config.py
```

3. Create a `.env` file in the `src` folder and add the secret values

4. If you run locally, make sure to have h5-aneurysm.h5 file in the root folder and the train.csv file. 

5. You can launch training either locally or on the cloud (SageMaker):
```bash
python src/run_training.py --mode local
```

or

```bash
python src/run_training.py --mode cloud
```
