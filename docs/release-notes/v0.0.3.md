# v0.0.3 Release Notes

## Highlights
- Output format switched from "nii.gz" (NIfTI) to "npz" (NumPy compressed) in preprocessing/pipeline.py, cli.py.
- Change image value size from float32 to float16 in preprocessing
- Added better error handlings in preprocessing pipeline: 
- Created a checkpoint for preprocessing
- Create a killing switch for preprocessing
- Added Gradient accumulation
- Changed the augmentation to be on GPU
- Change the sigmoid to be out of the model and change the criterion
- Accept different input sizes, but for each batch we pad all the series to the highest size in it.
- Optimize the training using Accelerate

## Motivation
- We needed smaller data to train our model and improve training speed; therefore, we applied NumPy compression offline and converted the data from float32 to float16.

- Some series fail to load because they contain images with different IDs within them. We added error handling to detect and display these issues in the pipeline.

- Due to parallelization, there was no safe kill switch to stop all active threads.

- Preprocessing can take up to 1 hour for 200 CTAs based on the computer and there might be unexpected errors that can stop the code, so we've created a checkpoint system such that you can stop anytime and continue from where you left on with the preprocessing. Also, the code works if we switch to all the data, having the subset already installed and continue with the rest of it.

- Our model is too large, and we cannot use a big batch size. To address this, we added gradient accumulation to simulate a larger effective batch size.


- The sigmoid operation inside the model can be a bottleneck, both computationally and numerically. The exponential function on the GPU is non-trivial to parallelize efficiently in bf16. Furthermore, during backpropagation, every element in the 3D output tensor must go through exp(), resulting in millions of extra exponential operations per batch.

- We need the data to be as small as possible. Previously, all volumes were sized 256×256×256, each with varying voxel dimensions, making the dataset too large (around 12.5 GB). Now, we crop and standardize the voxel size, while also allowing the model to accept variable input dimensions per batch.

- Accelerate provides many optimizations for PyTorch, so we decided to integrate it. Moreover, we plan to move the model to the cloud, and Accelerate supports Amazon SageMaker integration. Additionally, for future long training sessions, we can use checkpointing to prevent progress loss, and experiment trackers to monitor and showcase our experiments in more detail.

## Changes in Depth

### 1. `preprocessing/cli.py`
- Changed output format to npz

### 2. `preprocessing/pipeline.py`
- Got array from image, change to float16, save the compressed version and also added as additional information voxel_size, modality and pipeline_version. 

- Commented for the moment the overview, because we are not generating anymore the series as viewable. 

### 3. `preprocessing/workers.py`
- Added append_to_csv where after it is done with a file, it adds to the train.csv
- Added a csv reader to see how many files were already preprocessed and which of them (see load_done_ids() and the remaining_rows in run_in_process_batches)

### 4. `model/cli.py`
- Added gradient_accumulation as a global variable

### 5. `model/data_augmentation.py`
- For the moment there was commented the DataAugmentation class and added the `rotate_batch_gpu` that does the rotations on GPU

### 6. `model/data_loader.py`
- changed the output format to `.npz`
- Commented load_all_volumes and changed the split_data by working only with paths

### 7. Added `ds_config.json`
- This is the optimizer json file for DeepSpeed. The variables can be changed over time, this is the base optimizer. 

### 8. `model/model.py`
- Changed the model to be smaller
- Got rid of sigmoid done in forward pass

### 9. `model/training_pipeline`
- Added the functions: `custom_collate` that accept different input sizes per batch, `pad_collate_3d` that pads to a number divisible with 16 to the max D,H,W
- Changed all .float() to .to(torch.bfloat16)
- Added the StreamingDataset class that:
    - has a queue buffer to keep limited volumes in RAM
    - a background thread for async loading and shutdown() for safe termination
    - the model takes from the queue the volumes and the StreamingDataset will add more untill it's full. 
- train_dataset and val_dataset are taken from StramingDataset
- Added collate_fn to DataLoader
- Accelerator automatically handled devices
- Used an 8bit Adam Optimizer
- Changed criterion to BCEWithLogitsLoss
- Acceleator prepared the model and optimizers to be ran
- Used functions from accelerator for optimizations such as: 
    - accelerator.accumulate()
    - accelerator.backward()
    - accelerator.gather(loss)
    - accelerator.gather_for_metrics(predictions)
    - accelerator.unwrap_model(self.model)
    - accelerator.save(model)
- Applied the sigmoid 

## Benchmarks
| Dataset Variant                | Format               | Size        | Reduction  |
| ------------------------------ | -------------------- | ----------- | ---------- |
| Original 200 CTAs              | Raw DICOM            | **19.2 GB** | —          |
| Preprocessed CTAs (compressed fixed size) | Float32 NIfTI `.nii.gz` |**3.81 GB** | ↓ 5x |
| Preprocessed CTAs (cropped + compressed) | Float32 NIfTI `.nii.gz`| **3.52 GB** | ↓ 5.5×     |
| Preprocessed CTAs (cropped + compressed) | Float16 NumPy `.npz` | **2.01 GB** | ↓ **9.6×** |

## Migration

- Preprocess now with the new outputs `.npz`. Last version returned `.nii.qz`.
Run:
```bash
python3 -m preprocessing.cli
```

- Run new depndencies and make sure to be in the right environment: 
```bash
pip install -r requirements.txt
```

- Setup the accelerate
```bash
accelerate config
```

Make sure to be similar as those variables: 

```text
compute_environment: LOCAL_MACHINE
debug: false
deepspeed_config:
  deepspeed_config_file: model/ds_config.json
  zero3_init_flag: false
distributed_type: DEEPSPEED
downcast_bf16: 'no'
dynamo_config:
  dynamo_backend: INDUCTOR
  dynamo_mode: reduce-overhead
  dynamo_use_dynamic: true
  dynamo_use_fullgraph: true
  dynamo_use_regional_compilation: true
enable_cpu_affinity: false
machine_rank: 0
main_training_function: main
num_machines: 1
num_processes: 1
rdzv_backend: static
same_network: true
tpu_env: []
tpu_use_cluster: false
tpu_use_sudo: false
use_cpu: false
```

- Run the model:
```bash
accelerate launch -m model.cli
```
